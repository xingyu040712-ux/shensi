## 补丁基线

`patches/` 共 8 份最小统一差异补丁。符文文件合并了属性/lore 阶段及名称阶段，基线是属性迁移之前的原文件（SHA-256 为 `9d201ed5f33bdd8a37ec3a736751dcacab9a099d5fb6668658e7403db21044aa`）。其他 7 份使用横排修复前的原文件。已在线部署过的神四无需重复应用。

`deployment-manifest.json` 记录原始与最终部署文件的字节哈希及补丁路径。补丁采用 LF，原文件可能为 CRLF，因此应用后的文本一致与字节哈希一致需分别核验。全部 8 份补丁已在原配置的本地副本上通过 `git apply --check`，应用结果与最终上线配置文本一致。

## 使用与回退

1. 先备份上述 8 份目标配置，核对基线哈希。不要在已部署或基线不同的文件上强行套用。
2. 在包含 `plugins/` 的服务器配置副本目录，逐份执行 `git apply --check <补丁路径>`；全部通过后执行 `git apply <补丁路径>`，再解析 YAML 并核对预期差异。
3. 通过批准的运维方式同步对应 8 份配置，执行 `mm reload` 与 `yeegem reload`。本次实际部署未关服，未更换插件 JAR。
4. 使用新生成装备测试：打开 `/yeegem open 符文页面`，镶嵌、拆卸中间孔、复装、关闭界面及重登，检查始终只有一行符文且属性增量为单份。
5. 回退前另备份当前文件，成套恢复对应阶段配置并重载；不要混用不同阶段 GUI 与模板。符文 ID 回退需额外检查新旧镶嵌数据。

横排动作只处理带 `CXS4RuneLayout: horizontal-20261018` 的新装备，已有玩家装备未迁移。GUI 中央装备槽号为 40，调整 GUI 时须同步事件动作。只修改符文页面，原宝石页面保持原状。

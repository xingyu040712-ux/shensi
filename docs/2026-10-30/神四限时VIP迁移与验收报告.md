## 一并修复的权限库只读问题

实测发现，新玩家登录会被 LuckPerms 的 H2 只读错误阻止。根因是目标端 `zulu8.0.422/bin/java.exe` 的 Windows 强制完整性标签为 **Low**，启动后的 Java 进程也是 Low；H2 数据文件为 Medium。

Windows 对低完整性程序有禁止向上写入的限制，且进程创建会考虑可执行文件的完整性标签。这解释了“管理员账号、DACL 有写权限，数据库仍只读”的情况。[Microsoft MIC 说明](https://learn.microsoft.com/en-us/windows/win32/secauthz/mandatory-integrity-control) · [进程完整性策略](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-token_mandatory_policy)

已备份 Java 原文件及标签记录，仅将 **目标端 java.exe 的完整性标签从 Low 调整为 Medium**。没有更改其二进制内容，也没有修改全局 ACL、源端 Java 或数据库内容来规避问题。

Java SHA-256 前后一致：

```text
08E6475F7D2C2417B5C62FF883C42A7A904FBF397A99F7F245B0D5C4EB83C959
```

按原 BAT 和原 8G 参数正常重启后，新进程 PID 为 **3896**，完整性为 **Medium（S-1-16-8192）**，权限库和会员库 NIO 写入检测均通过。测试角色随后能成功创建权限记录、登录、注册并获得会员。

诊断期间曾建立无自动触发器的临时计划任务，现已移除。服务端最终仍由原 BAT 启动，启动文件未修改。
